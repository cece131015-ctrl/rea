# Website clones and mirrors

`clone_website` / `rea clone-website` makes a local copy of a web page from its
URL. `export_web_mirror` / `rea export-web-mirror` builds the same copy from a
saved `capture_browser_scenario` capture. Both use one shared workflow through
CLI and MCP.

```sh
export REA_BROWSER_EXECUTABLE=/opt/chromium/chrome
rea clone-website https://example.com/ /analysis/example-clone
rea clone-website https://example.com/ /analysis/example-site \
  --page https://example.com/about --page https://example.com/contact
rea export-web-mirror /analysis/scenario-capture.json /analysis/site-mirror
```

Open `index.html` in the output directory to browse the copy.

## What a clone does

`clone_website` launches the caller-selected Chrome or Chromium-family
executable (`browser_executable_path`, CLI `--browser`, or
`REA_BROWSER_EXECUTABLE`) with an owned temporary profile, loads the URL, waits
`settle_ms` after the load event, then visits each `additional_urls` entry in
order in the same session. REA does not download or install browsers.

The page's own JavaScript runs while it loads and it can contact any server,
exactly as in `capture_browser_scenario`. Every response body the browser
receives is retained within the selected budgets: `max_resource_bytes` per body
(default 16 MiB), `max_total_bytes` across bodies (default 128 MiB) and
`max_resources` network transactions (default 2,048). Bodies beyond a budget are
recorded as unavailable with their reason; nothing is silently dropped.

The complete capture Evidence is written as `capture.json` inside the clone. The
clone's own Evidence links to it and records its digest, so the mirrored bytes
remain traceable to the observation that produced them.

## Output layout

| Path                             | Contents                                                                  |
| -------------------------------- | ------------------------------------------------------------------------- |
| `files/<scheme>_<host>_<port>/…` | Exact retained bytes of every captured response, any origin and type      |
| `view/<scheme>_<host>_<port>/…`  | Browsable copies of UTF-8 HTML and CSS with captured references rewritten |
| `index.html`                     | Page generated by REA that opens the entry document                       |
| `capture.json`                   | Capture Evidence (clones only)                                            |
| `manifest.json`                  | Every transaction, its exact file, view, digests and coverage             |

Exact files are written with the capture's SHA-256 and byte count and re-read to
verify them. URL paths keep their layout under a readable origin directory.
Browsers loading `file://` pages infer types from extensions, so HTML documents
without `.html` and well-known types without a matching extension get one
(`/about` becomes `about.html`). Each distinct query string gets its own file
(`site.css?v=3` becomes `site~q<digest>.css`). Repeated responses with identical
bytes are written once. Different bytes for one URL, colliding paths and
unportable names are isolated under `files/isolated/` with a stated reason.
Redirect hops have no body; references to them resolve to the final response.

## Browsable view

View files are derived copies: only reference values are replaced, at their exact
source positions, and every other byte is preserved. HTML `src`, `href`,
`srcset`, `poster`, `data`, `background`, SVG `href`, `style` attributes and
`<style>` elements are handled; CSS `url()` and `@import` are handled with a
CSS Syntax Level 3 tokenizer, so URLs in comments and strings are ignored.

- A reference whose absolute URL (fragment removed) was captured points to the
  local view (HTML/CSS) or exact file, keeping the fragment.
- An uncaptured relative reference becomes absolute, so it never silently points
  at a missing local file. Opening it needs network access.
- Fragment-only, `data:`, `mailto:` and other non-HTTP references are unchanged.
- `<base href>` becomes `./`. `integrity` and `crossorigin` are removed only from
  elements whose reference now points to a local copy.

HTML or CSS that is not valid UTF-8, or that declares another charset, keeps
only its exact file. JavaScript is never rewritten: root-relative or computed
URLs inside scripts stay unresolved, Chromium does not run module scripts from
`file://` URLs, and opening the view runs the captured JavaScript in your
browser.

## Results and limits

The inline result is deliberately small: the entry document, coverage counts
(transactions, exported, unique files, redirects, unavailable, views, rewritten
and unresolved references), up to 50 unavailable resources with an omitted
count, the manifest digest and limitations. Per-resource records stay in
`manifest.json`.

A mirror contains only what the browser fetched during the capture. Unvisited
links, unused `srcset` candidates, lazy content and favicon requests the browser
does not report are absent. Response bytes are Playwright `Response.body()`
results, which can come from a credentialed follow-up load; the capture's
provenance limitation is carried into every manifest.

The output directory must not exist and its parent must exist. REA creates it
exclusively, writes the manifest last and commits; any failure or cancellation
rolls back the owned output and reports residual paths if rollback fails.

## Verification

`npm run verify:website-clone` clones a loopback fixture site through the public
CLI and stdio MCP with a real browser (`REA_BROWSER_EXECUTABLE`), checks the
exact files against the capture digests, and opens the view over `file://`.
